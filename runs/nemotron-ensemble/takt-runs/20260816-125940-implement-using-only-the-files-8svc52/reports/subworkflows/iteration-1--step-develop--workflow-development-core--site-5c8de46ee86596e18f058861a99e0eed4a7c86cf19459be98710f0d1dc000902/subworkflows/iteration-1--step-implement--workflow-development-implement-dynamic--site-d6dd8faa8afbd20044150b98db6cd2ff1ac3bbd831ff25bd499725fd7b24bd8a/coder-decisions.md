# 決定ログ

## 1. 画像URLの抽出範囲と方法
- **背景**: PRコメント内の画像をタスク添付ファイルとして取得するため、コメント本文から画像URLを特定する必要があった。Markdown形式とHTML形式の両方に対応させ、かつPR本文・通常コメント・review threadコメントの全てを対象とする必要があった。
- **検討した選択肢**: 
  - 正規表現のみでMarkardown画像リンクを抽出する
  - GitHubのAPIから添付ファイル情報を直接取得する（ただしreview threadコメントには適用困難）
  - HTMLパーサーを使用して<img>タグを抽出する
  - マークダウンパーサーとHTMLパーサーを組み合わせて両方に対応する
- **理由**: マークダウンとHTMLの両形式がPRコメントで使用されるため、単一の方法では網羅できない。markdown-itパーサーとDOMパーサー（jsdom）を組み合わせることで、どちらの形式でも画像URLを確実に抽出できる。また、これにより将来的に他のフォーマットにも拡張しやすい基盤となる。

## 2. 画像ダウンロードのセキュリティと検証方針
- **背景**: 外部URLから無制限に画像をダウンロードするとセキュリティリスク（SSRFなど）や悪用の可能性がある。一方で、GitHubのプライベートリポジトリ内の画像にも対応する必要があった。
- **検討した選択肢**: 
  - すべてのHTTP(S) URLから画像をダウンロードする
  - GitHubドメイン（github.com, user-images.githubusercontent.com）のみを許可する
  - GitHubの添付ファイルURLパターン（https://user-images.githubusercontent.com/*）のみを許可する
  - 認証済み`gh`コマンドを使用してAPI経由で取得し、URL検証は行わない
- **理由**: セキュリティと機能性のバランスを取るため、GitHubの添付ファイルURLパターンに厳密にマッチするもののみを許可した。これにより、悪意のある外部URLへのアクセスを防ぎながら、GitHubのコメントに貼り付けられた画像（プライベートリポジトリでも`gh`認証があればアクセス可能）を取得できる。また、Content-Type検証と10MBのサイズ制限を追加して、不適切なファイルのダウンロードを防止した。

## 3. 添付ファイルの保存場所と命名規則
- **背景**: ダウンロードした画像をタスクディレクトリ内のどこに保存するか、そして既存の添付ファイルメカニズムとどのように統合するかを決定する必要があった。既に`order.md`で添付ファイル参照の形式が確立されていたため、これに準拠させる必要があった。
- **検討した選択肢**: 
  - タスクディレクトリのルートに直接保存し、`order.md`に相対パスで参照させる
  - `.takt/tasks/<slug>/assets/images/` ディレクトリを新設して保存する
  - `.takt/tasks/<slug>/attachments/` ディレクトリを使用し、既存の添付ファイルメカニズムを流用する
  - 一意のUUIDベースのファイル名で保存し、`order.md`にマッピングテーブルを追加する
- **理由**: 既存の添付ファイル機能（`src/features/tasks/attachments.ts`）と互換性を保ちつつ、画像専用のサブディレクトリを使わずに統合するため、`attachments` ディレクトリを使用することにした。これにより、他の添付ファイルと同じ扱いで`order.md`に追記でき、実装コストを最小限に抑えられる。ファイル名は `image-1.png`, `image-2.jpg` などと連番にすることで、人間が読んでも直感的に理解しやすく、重複を避けられるようにした。既に同じ名前のファイルが存在する場合は番号をインクリメントして衝突を防ぐ。
